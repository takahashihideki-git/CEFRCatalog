# 書物層の検品レシピ

CLAUDE.md の「書物層には専用ゲート `tools/book_style_check.py` がある」の6観点を、毎回の受け取りで回すための手順と、当たりやすい着眼点。スクラッチの `.py` で行う（照合の中身は精読で、ゲートに足さない）。

## まず登録と実効を見る

- 新しい章・肖像が `book_style_check.py` の `SHEET_REGISTRY`／`PORTRAIT_REGISTRY`（第3部の章は `P3_SIX_FIELDS` も）に登録されているか。登録漏れは赤くならず、検査対象外になるだけ
- 登録が実効かを破壊テストで確かめる（下の「反例の作り方」）

## いちばん当たる着眼点：範囲を書かない最上級・唯一・全称

「この本でいちばん早い」「この本で唯一」「〜はこの章だけ」「近い文はない」── 帳簿では範囲つきで正しい主張を、書物が範囲を落として全体化すると偽になる。読者はその反例をすでに読んでいることが多い。

- 最上級・唯一・初出・全称・数で閉じた列挙（「この三つ」）を全部拾い、**主張の範囲を明示して正準で数え直す**。「全行為」なら第2柱も母数か、「聞く・読む言葉」なら範型183か受容209（肖像の素材込み）か、を詰める
- 第3部の全称は、名指しされた章だけでなく **全 p3 シートの `en`** を grep してから通す。原文の語の唯一性（「〜程度に」＝*enough to*、「容易に」＝*easily/readily*）は作業訳でなく `en` で引く
- **但し書きの語の出入り**（「Xの但し書きはA2で外れB1で戻る」）は、その語を全段の `en` で引く（カタログ45：*short* は A2+ の181にもあった）
- 書物だけ直して閉じるとは限らない。同じ主張がシートの DISCUSSION・delta にもあることが多い（その場合は `.py` と JSON の両方）。逆に帳簿が正しく書物の全体化だけが誤りのこともある。**どちらかを先に決めてから指摘を書く**

## 6観点のうち機械化できる部分

1. **段の集合＝シート行集合**：`### 見出し` の No. を集めて `rows` と比較（過不足・重複）。レベル表示と `level` の一致も見る。順序は照合しない（`##` の下位区分に割れてよい）
2. **本文が挙げる全 No. の出自**：`No\.[\d,\s、・/／]+` で群ごと拾い、全 `catalog_*.json` の逆引きに当てる。シート外なら篩DROP・留置でないか。英語例文の `No.4 bus` は目視で落とす
3. **散文のレベル帯 ⇔ シートのレベル**：見取り図・議論の帯言及を出し、モード別の min/max と突き合わせる
4. **参照の位置中立**：読了前提の言い回し（`で見た` `見たとおり` `読んだ読者` `思い出して` `すでに`）を文単位で拾い、名指しする章を `deliverables/CEFRカタログ_書物目次.md` の順序と突き合わせる。既知の語形は検査5.7が持つ（登録語形はツール側が正）
5. **他章の No. についての主張の裏取り**：「No.640からNo.633へ」のような言及は、相手の行の `jp`/`delta`/`en` を引いて合っているかを見る
6. **原文の限定句の保存と例文の適合**：段ごとに `en` の条件句・様態句・範囲句を列挙し、見出し・場面（読むもの等）・分かること・段の位置のどれかに残っているかを指差しで見る。落ちるのはほぼ様態・範囲句。あわせて例文が記述文の対象を実演しているか（語彙チェッカーはレベルしか見ない）

## 帳簿側を先に読む

- 疑わしい散文は、その章のシートの `discussion`／`delta` を先に読む。帳簿の書き分けを保存しているだけのことがある（取り下げになる）
- **書物の比較文は帳簿の元の文と突き合わせる。** 書物は帳簿の列挙から一つ落とすことがある（カタログ45：最近傍三つのうち一つを落とし、残りを「いちばん近い」と言った）
- 糸・相・族の帰属を指摘する前に正準台帳まで降りる（第2柱は `data/p2_threads.json` の主タグ／副タグが正準。delta 冒頭の「〜糸：」は写しで、ずれることがある）
- 当該行為を名指ししている**他の柱の帳簿**を第1報の時点で grep する（柱をまたぐ係留は書物側が拾い損ねやすい）

## 反例の作り方（登録の実効を確かめる）

章ごとに、(a) `jp` 一字改変 (b) 「例」欄の例文一字改変 (c) 出典No集合の欠落 (d) 本文のNo.引用の削除、第3部の章は四欄（読むもの・分かること・落とし穴・前の段から）の一字改変と、空欄の段への落とし穴欄の追加。踏んだ罠：

- **末尾に1字足す改変は効かない**（元の文字列を含んだまま）。末尾1字を**差し替える**
- 例文はイタリック記号が文字間に挟まることがある。文字間に `\*{0,2}` を許した正規表現で当てる
- データ層照合は jp＝段ブロック内、例文＝段の「例」欄のリスト行に閉じている。**反例は「例」欄の1箇所だけを改変する**。見取り図側だけを改変したら緑になるのが設計どおり（それも1件入れる）
- 束エントリ（見出しに複数No.）は例文行ごとの帰属ラベルが要る。サブリスト間の付け替え・帰属ラベルの脱落・複数No.・表記ゆれも反例になる
- 1行章は出典Noを削除できない（番号を改竄する側に倒す）。群引用（「（No.324, 622）」）はリテラル除去では本文が変わらない
- **反例が本文を1文字も変えていないことをテスト側で検出する**（`assert anchor in orig` を反例ごとに1行）。アンカーは正準ファイルから切り出す（半角 `)` と全角 `）` の取り違えで空振りした実例がある）

## 字数を照合するとき

申し送りの「全角換算N字」は、ロードマップと同じ数え方（生の全文・W/F/A を1.0、それ以外0.5）でしか合わない。`tools/roadmap_measure.py` の `width()` を使う。空白を除いて数えると逆向きの指摘になる。

## その他の事実上の規約

- 出典行のNo.順＝段順は機械照合されない（ゲートは集合のみ）が、ほぼ全章で成立している。段を動かす修正が入ったら見る

## 教訓（書物層）

- 用字の一律遡及の直後の補遺は、書き換え段落が旧文面ベースで回帰しうる ── 遡及語を毎便 grep する
- 語の一律置換の遡及は、層名でない複合語（音形・文字の形）にもかかる。ゲートは六欄だけを見るので、議論欄の過置換は緑のまま通る ── 置換語の新出現を全件表示して確かめる
- 「同文」「≡」は全対を `en` 逐語で引く（≡は近い文を含む略記）
- 章の比較文（「〜より多い」）は、相手シートの `l1` を同じ分類で数えてから通す。帳簿の区分名が全メンバーの原文に当てはまるかは帳簿の便で見る
- 「§5のこの要因はこの章だけ」は、『受容の課題』§5本文が例に引く段を先に見る
- 実在の年・都市を名指す創作例は史実を引いて確かめる
- 列挙に混ざった別種のもの（「読み返し」の列挙に辞書・時間の段）は、列挙の基準語を全件の `en` で引いて分ける
