# 現行仕様 ── 共通（読む順・不変条件・帳簿・書物・進め方）

> この文書と「現行仕様・第3部」「現行仕様・第4部」が、執筆を始める前に読む仕様である。ここに書いてあるのは、いま効いている規則だけ。規則がなぜそうなったか（経緯・根拠・初稿の失敗・補遺の明細）は引き継ぎ書§2（判断の記録）にあり、必要なときに記号で引く。散文の規律は執筆要綱、書物の様式と変換規則は書物目次が正で、ここには写さない。

## 1. 読む順と、読まなくてよいもの

1. 企画書（何を作るか）── 先に読む。読まずに始めると、確定した判断へ揺り戻す (j)
2. 現行仕様・共通 → その部の現行仕様
3. 執筆要綱（散文の規律1〜12と用字）
4. 指示書（その章の作業）と素材票（その章の原文・級・帳簿の分類を正準から機械で作った表）
5. 書く章の帳簿と、姉妹章を一本

**通読しない**：引き継ぎ書（§1＝周ごとの経緯、§2＝判断の記録）・README「いまどこ」の過去の周・書物ロードマップ・拡張構想メモ。判断の記号（「→(cs)」）を見て、要るときにその項だけを開く。

## 2. 不変条件

- No. が正準ID。原文（en）とレベルは `data/descriptors_en_1224.json` と一致する
- 作業訳（`data/working_translations_1224.json`）が正。公式訳（ゲーテ版）は照合・引用だけ (f)
- 全数シートの en／jp は生成時に data から取る（単一情報源）
- 器（スキーマ・章の様式）を変えるときは判断を記録し、**同じ便で現行仕様を書き換える**（下の5.）

## 3. 帳簿

- **二重管理**：作業訳＝`analysis/ja_tr1〜9.py` と JSON／篩＝`analysis/verdicts.py` と `data/sieve_verdicts_*.json`／全数シート＝`prototypes/*_full_prototype.py` と `catalog_*.json`／章＝`prototypes/build_*_chapter.py` と章の md（生成する章だけ）。片側だけ直さない。同期は `tools/source_sync_check.py` が見る
- 参照台帳（`data/crossrefs.json`）にエッジを足すときは、読みの散文（delta か DISCUSSION）が先。既存帳簿が所有する参照種は載せない (ai)
- 例文：`tools/exponent_level_check.py` を通し、超過・未収録に裁定を付ける（裁定は `tools/exponent_allowlist.txt`）。レベル保証は行為の枠に掛け、目的語のスロットは可変域として扱う。ただし目的語も記述文に合っていること (s)(s)-1
- 例文は記述文を演じる。記述文に合わない目的語・素材を置かない（語彙チェッカーはレベルしか見ない）

## 4. 書物

- 様式（章・肖像・巻頭・総括章）と変換規則1〜9は書物目次「様式の正準」が正
- 無改変転写：「できること」（作業訳）と「例」。第3部・第4部では四欄も（六欄）。照合は `tools/book_style_check.py`。新しい章は `SHEET_REGISTRY`（第3部は `P3_SIX_FIELDS`、第4部は `P4_SIX_FIELDS`）に登録する ── 登録漏れは赤くならず、検査対象外になるだけ
- **器は既定の形であって、章の構成は原文が決める**。書く前に、その尺度の記述文が求めていること（動詞と目的語）で梯子を分ける。中見出し（`##`）は梯子で、その下に下の級から上の級への段が並ぶ（第1部・第2部・第3部。第3部はカタログ49の Hideki 裁定で条件の区分から改めた）。梯子が何本あるかは見取り図で先に立てる。一つの梯子にしか当たらないことを、章全体のこととして書かない（カタログ49）。書物では系列を「線」と呼ばない（規律8）
- 他の章について言う前に、その章の本文を開く。記憶や型で言わない（カタログ49）
- 書いたら、読者として通読してから出す。ゲートが緑であることは、章が読めることの証拠にならない（カタログ49）

## 5. 記録と運用

- **現行仕様が正、判断の記録は履歴**。規則を変える判断を出すときは、同じ便で現行仕様の該当項を書き換え、判断の記録の古い項に「→(xx)で改定」と印を付ける
- 判断の記録への追記は、章（または帳簿）が確定してから一度だけ
- ゲート5本（`restore.py`・`analysis/partition.py`・`tools/source_sync_check.py`・`tools/book_style_check.py`・`tools/exponent_level_check.py`）を通す。新設・改修した検査は、正準からの最小変異で赤くなることを1件以上確かめる
- 便の状態（どの便が統合されたか）は記憶で言わない。`git log` で確かめる
- **分担（案、立て直しの間）**：執筆スレッドは散文（扉・見取り図・中見出し・段の欄・議論）を Hideki と書き、精読を受ける。検品係（Claude Code）は、素材票の作成、判断の記録・現行仕様・README の更新、生成ソースの再生成、横断の grep と追随、ゲート、コミットを引き受ける
- 進め方：指示書一枚＝一つの仕事。段階ごとに本文を見せて止まる（扉と見取り図 → 梯子ごとの中見出し → 段の欄 → 議論）
