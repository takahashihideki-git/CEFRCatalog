# CEFRカタログ

CEFR（ヨーロッパ言語共通参照枠）増補版2020の全能力記述文を、**発語内行為・受容・仲介の三カタログ＋横串のhow well**として再構造化し、日本の英語学習者に「CEFRの全貌」を具体とともに手渡すプロジェクト。株式会社トピックメーカー（enhack.app）。

このリポジトリは、生成AIとの探求セッション（スレッド「CEFRカタログ0, 1, …」）を横断して、設計判断・分析データ・成果物を共有するための単一情報源（single source of truth）。

## いまどこにいるか

- **グランドデザイン**：CEFRカタログ2で**四本柱＋横串へ補正**（発語内行為／産出・談話構築／受容／仲介＋how well。全1,224件の完全分割被覆を機械検証済み：`data/block_partition_1224.json`）
- **第0層：分析台帳**（全数集計・作業訳・言語行為論的篩・発語内行為インベントリ・区分分割）── 完成
- **第1層：カタログ** ── 帳簿（全数シート）は四本柱の43枚がそろった（第1柱22＋第2柱7＋第3柱11＋第4柱3）。書物層（`deliverables/book/`）は巻頭・第1部22章・級の肖像7本・総括章・第2部7章・第3部11章・第4部2章（全18章のうち）まで既稿
- **いまの周（2026-11-18〜、判断(dk)(dl)）**：**帳簿を読者に渡せる言葉に整えてから散文化する**（提案A、Hideki裁定）。第1部183行・第2部115行の四欄から帳簿の語を掃く（第3部・第4部は判断(bs)(cv)で済んでいる）。最初の一枚は**苦情・クレーム**（9行）で、指示書と素材票はリポジトリ直下（`指示書_苦情クレーム_帳簿の言葉直し.md`・`素材票_苦情クレーム.md`）。次＝掃いた帳簿の受け取り
- **第2層：問題集**（カタログを種に生成AIが増殖させるインスタンス）── 未着手

詳細は `deliverables/CEFR全貌カタログ_企画書.md`（グランドデザイン）と `deliverables/CEFRカタログ_現行仕様_共通.md`（いま効いている規則）を参照。経緯と判断の根拠は `deliverables/CEFRカタログ_引き継ぎ書.md`（記録）。

この節は**現在地だけを書き換える場所で、経緯は書き足さない**（周ごとの経緯は引き継ぎ書§1、判断は§2）。2026-11-19に、ここへ一行で積もっていた第1周〜カタログ52の経緯（約6万字）を畳んだ ── 各段落は§1に同じ周の段落があり、引いていた判断はすべて§2にある。旧文は `227883c` の README で引ける。

## 開発体制（claude.aiスレッド ↔ Claude Code の循環）

```
リモートリポジトリ (GitHub)
   │  clone / pull（スレッドがリポジトリを読む。単発のファイルだけ要るときは raw URL でもよい）
   ▼
claude.ai「CEFRカタログn」スレッド
   │  分析・設計判断（Hidekiと合意）・生成・検証
   │  成果は 申し送り_ClaudeCode.md＋パッチ＋更新ファイル として download
   ▼
Claude Code on Hideki local PC（ローカルリポジトリ）
   │  申し送りに従って適用 → 検証（restore.py ほか）→ commit → push
   ▼
リモートリポジトリ ──（次スレッドが pull して再開）
```

- **claude.aiスレッドはリポジトリへ直接pushしない**。変更は必ずパッチセット（申し送り＋diff＋必要に応じ更新ファイル実体）として渡す。分担の表は引き継ぎ書§6「分担」にある ── 執筆スレッドは帳簿・章・申し送り・パッチまで、検品係（Claude Code）が適用・ゲートの外の精読・コミット・push・クローズ時のロードマップの測り直しを担う。`CLAUDE.md` は前半（「原典ファイルはコミットしない」まで＝データを変えるときの規律）を両者が守り、後半（「成果物の受け取りと統合」から＝受け取り・検品・クローズ・WSL・git）は検品係の作業で執筆スレッドは適用しない（冒頭の断り、`3251791`）。
- **Claude Code が適用・検証・コミットを担う**。適用後の検証は `python3 restore.py`（第3周-0以降は `python3 tools/exponent_level_check.py` の実行確認を含む。カタログ16以降は `python3 tools/book_style_check.py` ＝書物ゲートの機械化部分も含む。カタログ51以降は `python3 tools/trace_check.py` ＝層をまたぐ出自も含む。精読ゲートは別途）＋**数字を持つ生成器の自走確認**（`python3 analysis/partition.py` ほか ── 参照名・数字を変更したソースは参照の書き換えだけで済ませず必ず実行して確認する。CEFRカタログ6・第三陣適用時のEXPECTED_SUB追随漏れの教訓）＋**生成ソース同期点検**（`python3 tools/source_sync_check.py` ── 成果物JSONだけが更新されて生成ソース側が取り残される事故が3回起きたため常設ゲート化。全数シート43枚〔第1柱22＋第2柱7＋第3柱11＋第4柱3〕のbuild()・旧範型9枚の全10列・`verdicts.py`↔篩帳簿・`ja_tr1〜9.py`↔作業訳を照合）。
- **申し送りの適用手順は `git apply`＋自前コミットメッセージ（Co-Authored-By付き）で書く**。`git am` は使わない ── コミット作者はTakahashi Hideki名義で統一し、スレッドの寄与はCo-Authored-Byで記録する（CEFRカタログ6で確立）。
- 設計判断はスレッド側で合意してから実装する（confirm → agree → edit → verify → output）。判断と根拠は引き継ぎ書§2に、周回の進捗は引き継ぎ書§1に記録し、README「いまどこにいるか」は現在地だけを書き換える。

## 新スレッドでの再開手順

1. **この順で読む**：`deliverables/CEFR全貌カタログ_企画書.md`（何を作るか）→ `deliverables/CEFRカタログ_現行仕様_共通.md`（いま効いている規則と読む順）→ その部の現行仕様 → `deliverables/CEFRカタログ_執筆要綱.md` → その仕事の指示書。**企画書を読まずに始めないこと**（CEFRカタログ2で、企画書未読のまま確定済み設計判断への揺り戻しが起きかけた実績あり）。引き継ぎ書は記録で、通読しない（判断(cz)、カタログ49）。
2. **リポジトリを clone（既にあれば pull）して読む** ── 指示書・素材票・現行仕様・帳簿・章はすべてリポジトリにある（検品係が push したものが正。スレッドは push しない）。単発のファイルだけ要るときは raw URL でもよい（例：`https://raw.githubusercontent.com/takahashihideki-git/CEFRCatalog/main/data/descriptors_en_1224.json`）。あわせて実例語彙チェッカー（`tools/exponent_level_check.py`）が参照するCEFR-Jデータ `https://github.com/openlanguageprofiles/olp-en-cefrj.git` も同階層に clone してください（詳細は「語彙レベル照合データ」節）。
3. 指示書（なければ引き継ぎ書§7の生きた留保）の続きから再開。第3部（受容）の作業に入るときは `deliverables/CEFRカタログ_受容の課題.md` も必読（理解の七層・落とし穴の判定・欄の分担・章名の正準）。
